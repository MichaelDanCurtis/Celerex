# Agent on Kubernetes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the Celerex Agent (`celerex-api`) + Postgres in a `celerex` namespace on the local Docker Desktop Kubernetes cluster, reachable by the local Design daemon at `http://localhost:30001`, and use it to prove the 2f routine→Ritual migration live.

**Architecture:** A multi-stage Dockerfile builds `celerex-api` from a *staged* build context that includes the Celerex workspace + the sibling-repo `galvo-federation` crate. Kustomize base manifests deploy an in-cluster Postgres (PVC) + the Agent (Deployment + NodePort 30001), with required secrets generated locally and never committed. Scripts (`up.sh`/`down.sh`) build the image and apply/tear down.

**Tech Stack:** Rust/Axum (`celerex-api`, edition 2024), Docker, Kubernetes (Docker Desktop), Kustomize, Postgres 17.

**Spec:** `docs/superpowers/specs/2026-06-14-agent-on-k8s-design.md`
**Repo:** Celerex. **Branch:** `feat/agent-on-k8s` off main.

**Recon facts (relied on by this plan):**
- Workspace members: `packages/backend/api`, `packages/backend/agent-orchestrator` (no external path deps). The ONLY cross-repo path dep is `galvo-federation` at `../../../../lucidity/Galvo/engine/galvo-federation` (its only intra-Galvo path dep, `galvo-hub`, is dev-only → not needed for the release build).
- No compile-time `sqlx` macros → no DB / no `.sqlx` at build time.
- Required env: `DATABASE_URL`, `CELEREX_CRED_KEY` (pod crash-loops without it), `CELEREX_JWT_SECRET`. Binds `0.0.0.0:3001`. Migrates on boot.
- `GET /api/providers` is unauthenticated → health probe target.
- `Cargo.lock` is present (reproducible build).

## Task 1: Dockerfile + staged build-context script

**Files:** `deploy/docker/agent.Dockerfile`, `deploy/docker/build-image.sh`, `deploy/docker/.dockerignore`

- [ ] **Step 1: Write the Dockerfile**

Create `deploy/docker/agent.Dockerfile`:

```dockerfile
# Multi-stage build for celerex-api. The build context is a STAGED dir assembled
# by build-image.sh that preserves the sibling layout the Cargo path deps expect:
#   <context>/Celerex/...            (the workspace)
#   <context>/lucidity/Galvo/engine/galvo-federation   (cross-repo path dep)
FROM rust:1-bookworm AS builder
WORKDIR /build
COPY Celerex/ Celerex/
COPY lucidity/ lucidity/
WORKDIR /build/Celerex
RUN cargo build -p celerex-api --release

FROM debian:bookworm-slim AS runtime
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates \
    && rm -rf /var/lib/apt/lists/*
COPY --from=builder /build/Celerex/target/release/celerex-api /usr/local/bin/celerex-api
EXPOSE 3001
CMD ["celerex-api"]
```

- [ ] **Step 3: Write the staging + build script**

Create `deploy/docker/build-image.sh`:

```bash
#!/usr/bin/env bash
# Build the celerex-agent image from a staged context that includes the Celerex
# workspace + the sibling-repo galvo-federation crate (the only cross-repo path dep).
set -euo pipefail

IMAGE="${IMAGE:-celerex-agent:dev}"
# Repo roots (this script lives in Celerex/deploy/docker).
CELEREX_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
DEV_ROOT="$(cd "$CELEREX_ROOT/.." && pwd)"          # .../Development
GALVO_FED="$DEV_ROOT/lucidity/Galvo/engine/galvo-federation"

if [[ ! -d "$GALVO_FED" ]]; then
  echo "ERROR: galvo-federation not found at $GALVO_FED" >&2
  echo "The Agent build needs the sibling lucidity/Galvo repo checked out." >&2
  exit 1
fi

STAGE="$(mktemp -d -t celerex-build-XXXXXX)"
trap 'rm -rf "$STAGE"' EXIT

# Stage the Celerex workspace (manifests + lockfile + both member crates).
mkdir -p "$STAGE/Celerex/packages/backend"
cp "$CELEREX_ROOT/Cargo.toml" "$STAGE/Celerex/Cargo.toml"
cp "$CELEREX_ROOT/Cargo.lock" "$STAGE/Celerex/Cargo.lock"
cp -R "$CELEREX_ROOT/packages/backend/api" "$STAGE/Celerex/packages/backend/api"
cp -R "$CELEREX_ROOT/packages/backend/agent-orchestrator" "$STAGE/Celerex/packages/backend/agent-orchestrator"

# Stage the one cross-repo path dep, preserving its relative location.
mkdir -p "$STAGE/lucidity/Galvo/engine"
cp -R "$GALVO_FED" "$STAGE/lucidity/Galvo/engine/galvo-federation"

# Lean context.
cp "$CELEREX_ROOT/deploy/docker/.dockerignore" "$STAGE/.dockerignore"

echo "Building $IMAGE from staged context $STAGE ..."
docker build -f "$CELEREX_ROOT/deploy/docker/agent.Dockerfile" -t "$IMAGE" "$STAGE"
echo "Built $IMAGE"
```

- [ ] **Step 4: Make executable + build**

Run:
```bash
chmod +x deploy/docker/build-image.sh
./deploy/docker/build-image.sh
```
Expected: a successful `docker build`, ending `Built celerex-agent:dev`. (First build is slow — full Rust compile.)

> If the build fails on a missing path dependency other than `galvo-federation`, the host `cargo build -p celerex-api --release` is the oracle for what's required — add that crate dir to the staging step (preserving its relative path) and rebuild. If the `rust:1-bookworm` toolchain is < 1.85 (edition 2024), pin a newer tag (e.g. `rust:1.85-bookworm` or `rust:1.90-bookworm`).

## Task 3: up/down scripts + README + gitignore

**Files:** `deploy/k8s/up.sh`, `deploy/k8s/down.sh`, `deploy/k8s/README.md`, modify `.gitignore`

- [ ] **Step 1: up.sh**

Create `deploy/k8s/up.sh`:

```bash
#!/usr/bin/env bash
# Bring up the celerex Agent + Postgres on the local Docker Desktop cluster.
set -euo pipefail
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
CELEREX_ROOT="$(cd "$HERE/.." && pwd)"

kubectl config use-context docker-desktop >/dev/null
kubectl apply -f "$HERE/base/namespace.yaml"

# Create the Secret once (idempotent: skip if present). Real values never committed.
if ! kubectl -n celerex get secret celerex-secrets >/dev/null 2>&1; then
  PGPW="$(openssl rand -hex 16)"
  CREDKEY="$(openssl rand -hex 32)"
  JWT="$(openssl rand -hex 32)"
  kubectl -n celerex create secret generic celerex-secrets \
    --from-literal=POSTGRES_PASSWORD="$PGPW" \
    --from-literal=DATABASE_URL="postgres://celerex:${PGPW}@celerex-postgres:5432/celerex" \
    --from-literal=CELEREX_CRED_KEY="$CREDKEY" \
    --from-literal=CELEREX_JWT_SECRET="$JWT"
  echo "Created celerex-secrets."
else
  echo "celerex-secrets already exists; leaving as-is."
fi

# Build image into the Docker Desktop daemon (shared with the cluster).
"$CELEREX_ROOT/deploy/docker/build-image.sh"

kubectl apply -k "$HERE/base"
echo "Waiting for rollouts..."
kubectl -n celerex rollout status deploy/celerex-postgres --timeout=120s
kubectl -n celerex rollout status deploy/celerex-agent --timeout=180s
echo "Agent reachable at http://localhost:30001 (e.g. GET /api/providers)."
```

- [ ] **Step 2: down.sh**

Create `deploy/k8s/down.sh`:

```bash
#!/usr/bin/env bash
# Tear down the celerex deployment. Pass --purge to also delete the PVC + Secret.
set -euo pipefail
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
kubectl delete -k "$HERE/base" --ignore-not-found
if [[ "${1:-}" == "--purge" ]]; then
  kubectl -n celerex delete pvc celerex-postgres --ignore-not-found
  kubectl -n celerex delete secret celerex-secrets --ignore-not-found
fi
echo "Down."
```
